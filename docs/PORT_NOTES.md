# 어디서 무엇을 가져왔나

## 포켓몬 연구소 테마

공통 화면을 포켓몬 메카 연구소로 꾸몄다. 새 방문자의 기본은 밝은 연구소이며,
기존 사용자가 저장한 테마·밀도 선택값은 그대로 이어진다.

| 유지한 열쇠 | 새 테마 | 문양 |
|---|---|---|
| daylight | 포켓몬 연구소 | 몬스터볼 |
| midnight | 야간 도감 | 초승달과 별 |
| blossom | 페어리 가든 | 페어리 별빛 |
| moss | 상록숲 | 잎 |
| plum | 고스트 타워 | 유령 |
| sand | 피카츄 옐로 | 번개 |
| deep | 블루오션 | 물방울과 파도 |
| ember | 불꽃 체육관 | 불꽃 |

팔레트·배경은 `workspace.css`, 문양·테마 미리보기는 `workspace-ui.js`,
이름은 `words.js`에 있다. `workspace-theme.js`의 테마 목록이 고르개와
미리보기의 공통 기준이며 theme-color는 각 팔레트의 deck 색과 맞춘다.
CSS의 가짜 글자로 넣던 테마 이름도 낱말 표로 옮겼다.

홈은 도감·생성기 입구와 테마 미리보기로 바꿨다. 도감·생성기에서도 같은
팔레트와 문양을 사용한다. 화면 테마는 이미지 생성 화풍·프롬프트와 독립이다.

`tests/workspace-theme.cjs`는 저장 호환성과 색상 연결을,
`tests/theme-screen.cjs`는 여덟 테마·문양, 텍스트 대비, 페이지 이동 시 유지,
생성 프롬프트 불변, 344·690·1280px 화면을 검사한다.

아래는 가져오던 당시의 기록이다.

`polos0117/atelier` 에서 **주제와 무관한 것만** 가져왔다. 옮기면서 고친 것과
일부러 뺀 것을 적는다.

## 옮기면서 고친 것

**테마 이름을 함선에서 빛깔로.** 앞선 저장소의 여덟 테마는 건담 함선 이름이었다
(`midnight` · `white-base` · `archangel` · `musai` · `rewloola` · `agama` ·
`ptolemaios` · `isaribi`). 팔레트는 주제와 무관한데 **이름이 주제에 묶여 있었다.**
빛깔 이름으로 바꿨다.

| 옛 열쇠 | 새 열쇠 | 낱말 표 |
|---|---|---|
| midnight | `midnight` | 한밤 |
| white-base | `daylight` | 한낮 |
| archangel | `blossom` | 꽃빛 |
| musai | `moss` | 이끼 |
| rewloola | `plum` | 자두 |
| agama | `sand` | 모래 |
| ptolemaios | `deep` | 심해 |
| isaribi | `ember` | 잉걸 |

`.fleet-*` 클래스도 `.crest-*` 로 바꿨다 — "함대" 는 이 놀이의 말이 아니다.

**말을 낱말 표로.** `fresh.js` 의 안내문 넷과 겉모습 고르개의 이름표를
`lib/words.js` 로 뺐다. 옮기기 전에는 코드에 박혀 있었다.

**프롬프트 엔진 — 구조는 그대로, 말만 표로.** `toolkit-spec.js` → `lib/prompt-spec.js`
로 이름만 바꿔 통째로 왔다. 표 65개에 **함수는 하나도 없다** (원본도 그랬다).
조립부 둘(`prompt-anthro.js` · `prompt-lifestyle.js`)은 한글이 0자리라 손댈 게
없었고, 코드에 박혀 있던 영문 주제어 **7자리**만 표로 뺐다 —
`SOURCE_WORD`(셋)와 `SOURCE_INPUT`(블록 하나). `toolkit.js` 의 이름표 둘
(`CAT` · `LABEL`)과 요약 조각 넷도 표로 옮겼다. 이제 이 넷에는 한글도 주제어도 없다.

**옮긴 것이 같은 글을 내놓는지 바이트로 확인했다.** 화풍 6 × 형태 3 × 번역 3 ×
성별 2 = 의인화 **108벌**, 화풍 6 × 카테고리 6 × 성별 2 = 일상컷 **72벌**.
180벌 전부 원본과 한 글자도 안 다르다. (표에서 한 단어를 바꿔 이 비교가 실제로
차이를 잡는 것도 확인했다.)

## `prompt.html` — 화면 코드는 안 건드리고 선만 이었다

2,283줄을 그대로 복사한 뒤, **부르는 자리 다섯 곳만** 고쳤다. 화면 코드도 말도
손대지 않았다.

| 고친 것 | 어떻게 |
|---|---|
| `lib/toolkit-spec.js` | → `lib/prompt-spec.js` (이름이 바뀌었다). `lib/words.js` 도 같이 싣는다 |
| `data/mech.json` · `data/series.json` | → `data/card.json` · `data/group.json` |
| 카드 꼴 | `cardsOf()` 한 함수로 맞춘다. atelier 는 `cards` 가 통째로 한 배열이고 묶는 축이 `series` 였는데, 여기는 갈래(`kinds`)별로 나뉘고 축이 `element` 다. 화면은 계속 `series` 로 읽는다 |
| `play.html` 링크 | → `index.html` (드래프트 화면은 여기 없다) |
| `prompt.webmanifest` · `icon-prompt-180.png` | 뺐다. 그림이 생기면 붙인다 |
| `<title>` | 낱말 표의 `app.title` 과 맞췄다 |

`data/group.json` 에 `electric → 전기` 한 줄을 넣었다. 카드의 `element` 를 이 표로 읽는다.

**실제로 돈다.** 세 탭이 피카츄로 글을 뽑는다 — 의인화 21,671자, 단일 컷 8,582자,
콜라주 11,999자. `tests/prompt-screen.cjs` 17가지가 지킨다. 이은 자리를 하나씩
다시 끊어서 검사가 이름을 대고 실패하는 것도 봤다.

화면 말(한글 1,189자리)은 **안 뺐다.** `tests/words.cjs` 의 `PENDING` 에 적어 두고
자리 수를 늘 찍는다 — 늘어나면 실패하고, 다 빼면 그 줄을 지우라고 실패한다.

아직 안 맞는 것 하나: 목록에 "초상 완료 0 / 1기" 로 뜬다. 이 화면은 초상을
화풍 밑에서 찾는데 여기 초상은 폼(`byForm`) 안에 있어서다. 도감은 `coverOf` 로
풀었다 — 툴킷도 폼 축에 맞출 때 같이 본다.

## 카드 자료를 받아 왔다

`tools/fetch-cards.py` 가 PokéAPI 의 CSV 아홉 장을 읽어 `data/card.json` 과
`data/group.json` 을 만든다. 카드 **1,025장**, 묶음(타입) **18가지**.

세대별로 151 · 100 · 135 · 107 · 156 · 72 · 88 · 96 · 120 이고, 두 타입 526 ·
한 타입 499 다. 한국어 이름이 없는 종은 하나도 없었다.

직접 `pokeapi.co` 를 부르지는 못한다 — 이 환경의 프록시가 403 으로 막는다.
`raw.githubusercontent.com` 은 열려 있어서 CSV 쪽으로 갔고, 결과적으로 더 낫다
(호출 9번 대 1,025번).

카드 한 장이 드는 것: 이름·영문명·도감 번호·타입(둘까지)·세대·분류·키·무게·
종족값 여섯·색·모양·알그룹·진화 앞뒤·전설/환상·도감 설명. 종족값과 색·알그룹의
이름표는 `data/label.json` 이 따로 든다 — 카드에는 열쇠와 숫자만 넣는다.

한국어 도감 설명은 1,025 가운데 **898장**만 있다. 최신 세대는 아직 없다.
모양(shape)은 한국어 정본이 없어 영문 열쇠 그대로 뜬다(`quadruped` 처럼).

`data/card.json` 은 439 KB 이고 gzip 하면 101 KB 다. Pages 가 압축해 보낸다.

화면 둘 다 1,025장을 받아냈다. 도감은 310 ms 에 다 그리고 검색도 돈다.
툴킷 고르개에도 1,025장이 선다.

그러면서 걸린 것 둘:

- `tests/dex-forms.cjs` 가 **"첫 칸 = 그림 있는 카드"** 를 박아 두고 있었다.
  카드가 1장일 때는 맞았지만 1,025장이 되니 첫 칸이 이상해씨였다. 이름으로
  검색해 여는 꼴로 고쳤다.
- 값 판을 붙이면서 `Fragment` 를 `h.Fragment` 로 불렀다. preact 는 `Fragment` 를
  따로 내보내므로 `h.Fragment` 는 `undefined` 고, preact 가 그 자리에 진짜 태그를
  하나씩 만들었다. 격자에서 그 태그가 칸을 차지해 제목과 값이 세로로 겹쳐 붙었다.
  처음 쓴 검사는 "제목과 값이 24px 안에 있나" 로 재고 있어서 이걸 못 잡았다 —
  겹쳐 붙어도 20px 차이였다. 격자의 자식이 `dt`·`dd` 뿐인지 보는 것으로 바꿨다.
- `prompt.html` 이 `group.json` 의 **`order` 를 안 봤다.** 카드에서 처음 나온
  순서대로 늘어서서, `order` 를 고쳐도 화면이 안 바뀌었다. `group.json` 머리말이
  바로 그 함정을 적어 두고 있었는데 화면이 그대로 밟고 있었다. 고쳤고 검사가 본다.

## 화풍 `bright_catalog` 를 되살렸다

처음에 `data/style.json` 에 자리만 잡아 뒀던 열쇠다. 그림이 한 장도 없는 빈 열쇠라
화풍 통합 때 빠졌는데, 특별컷에 쓸 자리라 프롬프트 쪽에 제대로 넣었다.

`lib/prompt-spec.js` 에 `ART_STYLES` 줄과 `STYLE_PROFILES.bright_catalog`
(`core`·`anthro`·`lifestyle`)을 더하고 `node tools/sync-styles.cjs --write` 로
`data/style.json` 을 다시 만들었다. 화풍 12가지가 됐다.

내용은 밝고 고른 빛의 카탈로그 도판이다 — 전신 2:3, 카메라·빛·배경을 폼마다
똑같이, 글자 없음, 연출 절제. **나란히 놓고 견주는 것이 목적인 화풍**이라
도감의 "나란히 보기" 와 짝이 맞는다.

## `ART_STYLES` 의 네 번째 칸을 지웠다

`bright_catalog` 를 넣다가 찾았다. 화풍 줄이 `[열쇠, 이름, 한글 설명, 영문 본문]`
넷이었는데 **네 번째 칸을 아무도 안 읽는다.** 조립부(`styleBlock`)는 열쇠만 보고
글은 `STYLE_PROFILES[key].core` 에서 꺼내고, 화면은 `[0]`·`[1]`·`[2]` 만 쓴다.

그 칸에 뭐가 들어 있었냐면 **쪼개기 전 통짜 원본**이다. `photoreal` 로 보면

```
[3]    = core 앞부분 + "ARMOR AND MECHANICAL SURFACES: …" + core 뒷부분
core   = 그 armor 문단이 빠진 것
anthro = 그 armor 문단
```

원래 한 덩어리였던 글을 나중에 `core`(모든 컷 공통)와 `anthro`(의인화 컷에만)로
갈랐다. 일상컷에 장갑 얘기가 들어가면 안 되니까. 조립부는 갈라 놓은 쪽만 쓰고,
`[3]` 은 갈리기 전 것이 그대로 앉아 있었다.

**24,945자를 지웠다.** 돌아가는 데는 아무 영향이 없지만, 문구를 고치는 사람이
거기를 고치면 되는 줄 알 자리였다.

## 포켓몬 메카 생성기 전환

첨부 수정안과 후속 검토에 따라 성인 여성·확정한 기준 이미지·네 폼을
공통 생성기에 연결했다. 화면은 폼 초상·액션·일상컷 세 가지다.
초상은 비교 카메라를 고정하고, 액션과 일상은 각각의 장면 설정을 쓴다.
일상컷은 폼과 독립이며, 기준 이미지 모드에서는 최초 외형 값을 재주입하지 않는다.

복원된 `bright_catalog`를 포함한 12개 화풍 키·이름, 그림 파일명과 자료 구조는
유지했다. 화풍의 재질 표현과 인물·폼·카메라의 역할을 분리했다.
옛 거대 원본 템플릿·형태/번역 모드·설정 기록에서 외형 이어받기는 생성 경로에서 제거했다.

`prompt.html`은 로더가 되고 화면은 `lib/prompt-ui.js`·`lib/prompt.css`로 분리했다.
화면 문장은 `lib/words.js`로 옮겨 `tests/words.cjs`의 PENDING 예외를 없앴다.
기존 설정 저장값은 지우지 않으며 새 카드별 설정만 `pkm_prompt_v2`에 저장한다.
설정 내보내기나 콜라주를 새로 확장하지 않는다.

엔진·화면 검사를 새 동작에 맞춰 바꿨다. 기준 이미지 모드에 최초 외형 값을
일부러 섞었을 때 화면 검사가 실패함을 확인한 뒤 정상 동작으로 되돌렸다.
구체적인 규칙·API·검사 명령은 `PROMPT_REWRITE.md`에 기록했다.
